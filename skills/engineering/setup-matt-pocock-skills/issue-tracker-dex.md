# Issue tracker: dex

PRDs for this repo live as dex epics. Implementation issues live as dex tasks. Use the `dex` CLI for all operations.

## Conventions

- **Create an issue**: `dex create "$TITLE" --description "$BODY"`. Use a heredoc or shell variable for multi-line descriptions.
- **Create a PRD**: create a dex epic for the PRD. In current dex CLI terms, that means a top-level task created with `dex create "$TITLE" --description "$BODY"`. Put the PRD body in the description, starting with metadata identifying it as a PRD: `Issue-Kind: prd`, `Triage-State: needs-triage`, `Triage-Type: enhancement`.
- **Create implementation issues from a PRD**: create child tasks under the PRD epic with `dex create "$TITLE" --description "$BODY" --parent "$EPIC_ID"`.
- **Represent blockers**: use dex's native blocker support: `dex create "$TITLE" --description "$BODY" --blocked-by "$BLOCKER_IDS"`, `dex edit "$ID" --add-blocker "$BLOCKER_IDS"`, and `dex edit "$ID" --remove-blocker "$BLOCKER_IDS"`. `$BLOCKER_IDS` is comma-separated.
- **Read an issue**: `dex show "$ID" --full` for human-readable work, or `dex show "$ID" --json` for precise parsing.
- **List issues**: `dex list`, `dex list --json`, `dex list --all --json`, or `dex list "needs-triage" --json`. `dex list` only shows pending tasks by default; use `--all` if completed tasks matter.
- **Apply triage roles**: dex does not have labels. Store triage roles as metadata at the top of the task description: `Issue-Kind: issue | prd`, `Triage-Type: bug | enhancement`, `Triage-State: needs-triage | needs-info | ready-for-agent | ready-for-human | wontfix`. For dex, the roles in `docs/agents/triage-labels.md` map to `Triage-State` / `Triage-Type` fields in the task description. To change state, run `dex show "$ID" --full`, edit the description while preserving the body, then replace it with `dex edit "$ID" --description "$UPDATED_DESCRIPTION"`.
- **Add comments or triage notes**: dex has no comment stream. Append AI triage notes and agent briefs inside the task description under a `## Triage Notes` heading, then run `dex edit "$ID" --description "$UPDATED_DESCRIPTION"`. The triage skill's AI disclaimer must still be included at the top of each appended note: `> *This was generated by AI during triage.*`
- **Do not use `dex edit -n` for comments**: in current dex, `-n` means `--name`, not “note”.
- **Close an issue**: `dex complete "$ID" --result "$RESULT" --no-commit`. If implementation completed with a commit, use `dex complete "$ID" --result "$RESULT" --commit "$SHA"`. For `wontfix`, include the reason in `$RESULT`.

## When a skill says "publish to the issue tracker"

Create a dex task with `dex create`. For PRDs, create a dex epic (a top-level task) with `Issue-Kind: prd`. For implementation slices created from a PRD, create child tasks under the PRD epic with `--parent "$EPIC_ID"`.

## When a skill says "fetch the relevant ticket"

Run `dex show "$ID" --full` for human-readable context, or `dex show "$ID" --json` when precise parsing is needed.
